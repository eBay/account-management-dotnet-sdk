# ChangeLog

## 0.4.0 (11/17/2026)

### Breaking changes

#### Removed StrawberryShake types

The typed GraphQL client is now generated by the SDK generator instead of StrawberryShake. Every type that `AccountGraphQLClient` accepts or returns keeps its name, namespace (`EBay.AccountManagement.Generated.GraphQL`) and members. The result interfaces, result classes, input classes and enums are unchanged. Only StrawberryShake's own plumbing is no longer public:

- `IAccountManagementGraphQLClient`, `AccountManagementGraphQLClient`, and the per-operation `I{Operation}Query`, `I{Operation}Mutation`, `{Operation}Query`, `{Operation}Mutation` and `{Operation}{Kind}Document` types
- `AddAccountManagementGraphQLClient` (namespace `Microsoft.Extensions.DependencyInjection`). Use `AddAccountManagementSdk`.
- the `EBay.AccountManagement.Generated.GraphQL.State` namespace, `{Enum}Serializer` and `{Input}InputValueFormatter`
- input classes no longer implement `State.I{Input}Info`

#### GraphQL enum values renumbered

`UserRegistrationMarketplace` gains `EBAY_BENL` (eBay's GraphQL schema), which changes the numeric values of the members after it. Code that uses the member names is unaffected.

#### Simpler dependency injection

- `AddAccountManagementSdk` now registers only the configuration and a singleton `AccountManagementClient`. `AccountV1Client`, `AccountV2Client`, `FinancesClient` and `AccountGraphQLClient` are no longer registered individually: inject `AccountManagementClient` and use its `AccountV1`, `AccountV2`, `Finances` and `GraphQL` properties.
- The SDK no longer uses `IHttpClientFactory` or registers named `HttpClient`s, and no longer depends on `Microsoft.Extensions.Http`. To customise HTTP (proxy, client certificates, test doubles), use the new `AccountManagementClient(AccountManagementConfiguration, HttpMessageHandler)` constructor.

#### Trusted hosts

- The client constructors throw `InvalidOperationException` when a base URL uses a host that is not trusted (see Security). Add such hosts, for example a proxy, to `AccountManagementConfiguration.AllowedHosts`.

### Security

- The access token is sent only to trusted hosts. Before, it was attached to requests for any HTTPS host configured as a base URL.

### Added

- `AccountManagementConfiguration.AllowedHosts` for additional hosts trusted with the access token, and `AccountManagementConfiguration.DefaultAllowedHosts`. The eBay production hosts and their sandbox counterparts (for example `api.sandbox.ebay.com`) are trusted by default, so the sandbox needs no extra configuration.
- Target framework `net472` (.NET Framework 4.7.2).
- Typed GraphQL operations work with the standalone `new AccountManagementClient(config)` constructor. Before, they needed dependency injection.

### Changed

- Dependency minimums are lowered to the versions Kiota itself requires, so projects can keep older compatible versions: `Microsoft.Kiota.Bundle` >= 1.22.0 and `Microsoft.Extensions.DependencyInjection.Abstractions` >= 6.0.0. Previously the SDK required the newest 10.0.x packages. On .NET Framework the SDK requires `System.Text.Json` >= 10.0.0, matching the oldest supported .NET LTS (.NET 10). None of these minimums has a known vulnerability, and each release is tested at both the minimum and the latest versions.
- On .NET Framework the SDK's HttpClients allow 64 connections per host instead of the `ServicePointManager` default of 2.
- `AccountManagementConfiguration.HttpTimeout` and `RequestOptions.Headers` have `set` accessors instead of `init`, so projects compiled with C# 7.3 can assign them. Existing source compiles unchanged; recompile code that was built against 0.3.0.
- `GraphQL.ExecuteRawUnsafeAsync` under dependency injection now throws `UnauthorizedException` for HTTP 401 and `GraphQLException` for other non-2xx responses. It used to throw a raw `HttpRequestException`. Standalone mode already behaved this way.

### Fixed

- A GraphQL input object with no properties set is sent as `{}` instead of `null`. Before, a call such as `UserBiddingActivityAsync(new UserBiddingActivityInput())` failed because eBay rejects `null` for a required input. Passing `null` itself works as before: it is sent as `null` where the operation accepts it and rejected where it doesn't.

## 0.3.0 (09/25/2026)

### Added

- Target frameworks `net8.0` and `net9.0`, in addition to `net10.0`.
